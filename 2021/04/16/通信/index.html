Vue 组件通信：父子、兄弟、插槽与动态组件

2021-04-16 2265 字 5 分钟

为什么要理解组件通信

Vue 项目写到一定规模后，问题往往不是“会不会写组件”，而是组件之间的数据流是否清晰。组件通信混乱会带来三个问题：状态来源不清楚、子组件偷偷改父组件数据、兄弟组件之间强耦合。一个可维护的组件体系，应该让数据从哪里来、事件往哪里走、插槽负责什么，都有明确边界。

父传子：props 负责输入

父组件通过 props 向子组件传入数据。子组件应该把 props 当作只读输入，不应该直接修改。

<UserCard :user="currentUser" :editable="true" />
props: {
  user: { type: Object, required: true },
  editable: { type: Boolean, default: false }
}

如果子组件需要编辑 props，推荐复制到内部状态，或者通过 emit 通知父组件更新。不要直接写 this.user.name = 'new'，这会让数据流变得不可预测。

子传父：emit 负责输出

子组件不直接改父组件状态，而是通过事件表达意图。

<UserEditor :user="user" @save="handleSave" />
this.$emit('save', formData)

事件名建议表达业务动作，例如 save、submit、delete，不要写成 changeData 这类模糊名称。

兄弟通信：优先提升状态，而不是乱用事件总线

早期 Vue 项目常用事件总线实现兄弟组件通信，但事件总线容易造成“谁触发、谁监听”不透明。更推荐把共享状态提升到共同父组件，或者使用 Vuex/Pinia 这类状态管理工具。事件总线只适合很小的临时场景。

插槽：让父组件决定结构

插槽适合解决“子组件负责外壳，父组件负责内容”的场景，例如弹窗、卡片、列表项。

<BaseCard>
  <template #header>用户信息</template>
  <UserProfile :user="user" />
</BaseCard>

作用域插槽则适合子组件暴露局部数据，让父组件决定如何展示。

动态组件与 keep-alive

动态组件适合 tab、步骤页、可切换面板。配合 keep-alive 可以缓存组件状态，避免频繁创建销毁。

<keep-alive>
  <component :is="currentPanel" />
</keep-alive>

注意：被 keep-alive 缓存的组件再次展示时不会重新执行 created/mounted，需要在 activated 中处理“每次进入都要刷新”的逻辑。

实践建议

  • 父传子用 props，子传父用 emit。
  • 跨层级共享状态优先用状态管理，不要层层透传太多 props。
  • 插槽用于结构扩展，不要把业务状态藏进插槽里。
  • keep-alive 下区分 mounted 和 activated。

常见痛点

  • props 一路透传：页面层级一深，父组件需要把很多字段传给孙组件、重孙组件，中间组件只是“搬运工”。
  • 子组件直接改父组件数据：短期看能跑，后期很难判断状态到底是谁改的。
  • 事件总线滥用：任意组件都能 emit，任意组件都能 on，排查问题时很难找到触发链路。
  • 插槽和状态混在一起：本来只是 UI 扩展点，却把业务判断藏在插槽内部，复用时容易失控。

详细解决方案

写组件时先把“输入、输出、展示扩展点”分开。props 只表达输入，emit 只表达动作，slot 只表达结构扩展。这样组件的边界会非常清楚：父组件决定数据，子组件决定交互细节，插槽决定局部展示。

<UserEditor
  :model-value="form"
  @update:model-value="form = $event"
  @submit="saveUser"
>
  <template #footer="{ loading }">
    <button :disabled="loading">保存</button>
  </template>
</UserEditor>

如果多个页面都依赖同一份登录用户、菜单权限、主题配置，就不要继续 props 透传。把它放到 Pinia store 或 provide-inject 里，组件只读取自己需要的部分。对于弹窗、表格列、卡片头尾这类结构扩展，再使用插槽。

排查清单

  • 看到子组件修改 props，改成 emit 或 v-model 约定。
  • 看到兄弟组件互相监听事件，优先把状态提升到共同父组件。
  • 看到某个组件 props 超过 8 个，检查是否应该拆对象、拆组件或引入 store。
  • 看到 keep-alive 页面数据不刷新，检查 activated 和路由参数监听。
