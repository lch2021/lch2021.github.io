npm 是什么

npm 是 Node.js 的包管理工具，负责安装依赖、运行脚本、管理版本和发布包。前端项目基本都离不开 npm 或兼容工具。

初始化项目

npm init
npm init -y

执行后会生成 package.json，用来记录项目名称、版本、依赖和脚本。

安装依赖

npm install
npm install axios
npm install vite -D
npm install lodash@4

dependencies 是运行依赖，devDependencies 是开发依赖。构建工具、测试工具、类型工具通常放 devDependencies。

卸载依赖

npm uninstall axios
npm uninstall vite -D

运行脚本

{
  "scripts": {
    "dev": "vite",
    "build": "vite build",
    "test": "vitest"
  }
}
npm run dev
npm run build
npm test

查看和切换源

npm config get registry
npm config set registry https://registry.npmmirror.com

如果安装依赖很慢，可以切换镜像源。但发布包前要确认 registry 是否是官方源。

全局包

npm install pnpm -g
npm list -g --depth=0
npm uninstall pnpm -g

全局包适合命令行工具，不建议把项目运行依赖装成全局，否则团队环境不一致。

版本和锁文件

package-lock.json 记录精确依赖树，保证团队安装结果一致。不要随意删除锁文件；如果锁文件变化，要确认是否符合预期。

发布包

npm login
npm publish

发布前检查 package name、version、files、main/module/types 字段。已经发布的版本号不能重复发布。

常见排错

  • 安装失败：检查 Node 版本、网络、registry。
  • 命令不存在：确认依赖是否安装，脚本是否写在 package.json。
  • 依赖冲突：查看 peerDependencies 提示。
  • 构建和本地不一致：检查 lockfile 和 Node 版本。

GitHub 源码补充

这篇旧文也补了 GitHub 视角：不要只记 API 和命令，还要看真实仓库如何组织代码、文档、测试和配置。这样知识点会从“会背”变成“能排查、能落地”。

  • npm/cli：npm CLI 仓库和 changelog 能看到命令行为会随版本变化。团队项目要固定 Node/npm 版本，并把 lockfile 当作重要产物。
  • npm/rfcs：npm 新行为通常先在 RFC 中讨论。遇到 install、audit、publish 行为变化时，查 RFC 和 changelog 比搜索零散答案更可靠。

常见痛点

  • dependencies 和 devDependencies 混用：运行环境安装了大量不需要的构建工具。
  • lockfile 随手删除：团队成员安装出来的依赖树不一致，问题很难复现。
  • 全局包污染环境：本地命令能跑，别人电脑或 CI 上找不到。
  • registry 切换后忘记恢复：发布包时还指向镜像源，导致发布失败。

详细解决方案

团队项目建议把常用命令写进 scripts，而不是依赖全局命令。CI、本地、同事电脑都通过 npm run 调用同一套脚本。

{
  "scripts": {
    "dev": "vite --host 0.0.0.0",
    "build": "vite build",
    "lint": "eslint src",
    "preview": "vite preview"
  }
}

安装依赖时，普通业务运行包进 dependencies，例如 axios、lodash；构建、测试、类型、格式化工具进 devDependencies，例如 vite、eslint、typescript、vitest。部署环境如果只安装生产依赖，就不会漏掉真正运行需要的包。

排查清单

  • npm run 报命令不存在，检查依赖是否安装、脚本名是否正确。
  • 依赖冲突，优先看 peerDependencies 提示，不要盲目 --force。
  • CI 和本地结果不同，检查 Node 版本、npm 版本和 package-lock.json。
  • 发布失败，检查 registry、登录状态、包名、版本号和 files 字段。
