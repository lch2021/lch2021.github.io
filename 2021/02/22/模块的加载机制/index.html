Node.js 模块加载机制：缓存、路径与 node_modules 查找

2021-02-22 1918 字 4 分钟

模块加载为什么重要

Node.js 项目由大量模块组成。理解 require 如何查找和缓存模块，可以帮助定位“为什么加载的不是我想要的文件”“为什么代码只执行一次”“为什么模块找不到”。

模块类型

  • 核心模块：Node 内置模块，如 fs、path、http。
  • 自定义模块：项目内通过相对路径引入的文件。
  • 第三方模块：安装在 node_modules 中的包。

核心模块优先级最高

const fs = require('fs')

核心模块由 Node 提供，不需要安装。即使 node_modules 中存在同名包，核心模块仍优先。

自定义模块必须写路径

const utils = require('./utils')
const config = require('../config')

如果不写 ./ 或 ../，Node 会把它当作核心模块或第三方模块查找。

扩展名查找顺序

省略扩展名时，Node 会尝试按顺序查找：精确文件名、.js、.json、.node。

目录作为模块

当 require 指向目录时，Node 会先查该目录下 package.json 的 main 字段；如果没有，再尝试 index.js。

模块缓存

模块第一次加载后会被缓存。后续 require 同一个模块不会重复执行模块顶层代码，而是直接返回缓存结果。

// counter.js
console.log('loaded')
module.exports = { count: 1 }

多次 require counter.js，loaded 只打印一次。

node_modules 查找规则

第三方模块会从当前文件目录开始向上查找 node_modules，直到文件系统根目录。这解释了为什么子目录文件也能 require 根目录安装的包。

实践建议

  • 项目内文件使用相对路径或配置别名。
  • 不要依赖模块顶层副作用执行多次。
  • 包入口通过 package.json main 或 exports 明确声明。
  • 遇到模块找不到，先检查路径、安装位置和包入口。

常见痛点

  • 忘记写 ./：require('utils') 会去找核心模块或 node_modules，不会找当前目录 utils.js。
  • 误解模块缓存：以为每次 require 都会重新执行，结果状态被共享。
  • 包入口不清楚：package.json 的 main、exports、index.js 规则混在一起。
  • 依赖查找路径不明确：子目录能引用根目录依赖，但不知道 Node 是向上查找 node_modules。

详细解决方案

项目内模块建议路径明确，公共工具放到稳定目录，并通过构建工具或 tsconfig/jsconfig 配置别名。不要依赖“刚好能找到”的相对路径。

// 清晰：当前目录文件
const format = require('./format')

// 清晰：第三方包
const express = require('express')

模块缓存既是性能优化，也会带来共享状态。配置对象、数据库连接池适合复用；请求级别的数据不应该放在模块顶层变量里，否则不同请求会互相影响。

排查清单

  • MODULE_NOT_FOUND，检查路径是否缺少 ./ 或 ../。
  • 加载到错误文件，检查 package.json main/exports 和 index.js。
  • 状态串了，检查模块顶层是否保存了请求级变量。
  • 本地可运行线上失败，检查依赖是否在 dependencies 而不是 devDependencies。
