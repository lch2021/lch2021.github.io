Node.js 常用第三方包：从 cors 到 bcrypt

2021-02-27 1939 字 4 分钟

为什么要熟悉常用包

Node.js 生态依赖第三方包解决大量通用问题。熟悉常用包可以减少重复造轮子，但也要知道每个包解决什么问题、放在哪一层、有哪些安全风险。

cors：处理跨域

const cors = require('cors')
app.use(cors({
  origin: ['http://localhost:3000'],
  credentials: true
}))

开发环境可以放宽跨域，生产环境不要直接 origin: '*'，尤其是带 cookie 或 token 的接口。

jsonwebtoken：签发和校验 token

const jwt = require('jsonwebtoken')
const token = jwt.sign({ id: user.id }, process.env.JWT_SECRET, { expiresIn: '2h' })
const payload = jwt.verify(token, process.env.JWT_SECRET)

JWT_SECRET 必须放环境变量，不要写进代码仓库。token 里不要存密码、手机号等敏感信息。

bcryptjs：密码哈希

const bcrypt = require('bcryptjs')
const hash = bcrypt.hashSync(password, 10)
const ok = bcrypt.compareSync(password, hash)

密码不能明文入库，登录时比较 hash。即使数据库泄露，也能降低密码直接暴露的风险。

multer：处理文件上传

multer 用于处理 multipart/form-data。上传功能要限制文件大小、类型和保存路径，避免任意文件写入。

joi：参数校验

const schema = Joi.object({
  username: Joi.string().min(3).max(20).required(),
  password: Joi.string().min(6).required()
})

不要信任前端传参，后端必须做校验。参数校验失败要返回明确错误，但不要泄露内部实现细节。

dotenv：管理环境变量

require('dotenv').config()
const port = process.env.PORT || 3000

.env 不应提交到仓库，可以提交 .env.example 说明需要哪些配置。

选择第三方包的标准

  • 是否仍在维护。
  • 下载量和社区使用情况。
  • 安全漏洞记录。
  • API 是否简单稳定。
  • 是否真的需要引入，而不是几行原生代码可解决。

常见痛点

  • 包装了功能但不知道风险：例如 cors 全开放、JWT 密钥写死、上传目录不限制。
  • 所有依赖都装进 dependencies：构建工具、测试工具和运行依赖混在一起，部署体积变大。
  • 参数校验只放前端：接口被脚本直接调用时，后端没有兜底。
  • 密码处理不规范：明文保存或使用普通加密，安全风险很高。

后端依赖选择流程

Step 1明确问题类型
→
示例跨域 / 鉴权 / 上传 / 校验 / 配置
Step 2是否涉及安全边界？
→
是优先成熟维护包并限制配置
→
否评估是否原生能力已足够
Step 3上线前检查
→
产物环境变量、错误处理、日志、版本锁定

详细解决方案

一个比较清晰的 Express 项目可以按职责组织：入口文件只启动服务，中间件目录放 cors、鉴权、错误处理，routes 只定义接口路径，controllers 处理业务，validators 负责参数规则。

src/
  app.js
  middleware/auth.js
  middleware/error.js
  routes/user.js
  controllers/user.js
  validators/user.js

安全相关配置不要写死。CORS 的 origin、JWT_SECRET、数据库地址、上传目录都应该来自环境变量，并在启动时校验是否存在。

if (!process.env.JWT_SECRET) {
  throw new Error('JWT_SECRET is required')
}

排查清单

  • 跨域请求失败，先看浏览器 Network 的预检请求和响应头。
  • JWT 校验失败，检查签发密钥、过期时间、Authorization 格式。
  • 上传失败，检查 enctype、字段名、文件大小和 multer limits。
  • 线上启动失败，检查 .env、Node 版本和 lockfile 是否一致。
