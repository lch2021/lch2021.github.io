Vue Router 路由管理：从 routes 到导航守卫

2021-03-15 2235 字 5 分钟

路由解决什么问题

单页应用只有一个 HTML 页面，但需要根据 URL 展示不同组件。Vue Router 的职责就是把 URL 和组件对应起来，并管理页面跳转、参数、权限和嵌套路由。

核心概念

  • route：一条路由记录，描述 path 和 component 的关系。
  • routes：多条 route 的数组。
  • router：路由实例，负责跳转和守卫。
  • router-view：组件渲染出口。
  • router-link：声明式导航链接。
const routes = [
  { path: '/login', component: Login },
  { path: '/user/:id', component: UserDetail }
]

const router = new VueRouter({ routes })

动态路由参数

动态路由常用于详情页，例如用户详情、文章详情、订单详情。

this.$route.params.id

如果同一个组件在不同参数间切换，组件可能不会重新创建，需要 watch $route 或使用 beforeRouteUpdate。

编程式导航

this.$router.push('/login')
this.$router.push({ name: 'user', params: { id: 1 } })
this.$router.replace('/home')
this.$router.go(-1)

push 会新增历史记录，replace 会替换当前记录。登录跳转、错误页跳转经常用 replace，避免用户返回到无效页面。

导航守卫

权限控制通常写在全局前置守卫里。

router.beforeEach((to, from, next) => {
  const token = localStorage.getItem('token')
  if (to.meta.requiresAuth && !token) {
    next('/login')
  } else {
    next()
  }
})

常见问题

  • 路由跳转后页面不刷新：检查是否复用了同一个组件并只改变 params。
  • 权限守卫死循环：跳转登录页时要排除 login 自身。
  • 嵌套路由不显示：父组件中是否写了 router-view。
  • 刷新 404：history 模式需要服务端配置 fallback。

实践建议

路由表不要只写 path 和 component，建议补充 name、meta.title、meta.requiresAuth。这样后续做权限、面包屑、标签页和页面标题会更容易。

常见痛点

  • 路由表越写越乱：path、name、meta 缺少统一规范，后续权限和面包屑很难维护。
  • 导航守卫死循环：未登录跳登录页，但登录页本身又被守卫拦截。
  • 详情页切换不刷新：同一个组件从 /user/1 到 /user/2，组件被复用，mounted 不会重新执行。
  • history 模式刷新 404：前端路由正常，服务器没有 fallback 到 index.html。

详细解决方案

路由表建议统一使用 name 和 meta，不要只依赖 path。name 用于跳转，meta 用于权限、标题、缓存、菜单显示等横向能力。

{
  path: '/users/:id',
  name: 'user-detail',
  component: () => import('@/views/UserDetail.vue'),
  meta: { title: '用户详情', requiresAuth: true, keepAlive: false }
}

权限守卫只做“能不能进”的判断，不要把复杂业务请求全部塞进去。已经登录访问登录页，可以 replace 到首页；未登录访问受保护页面，可以携带 redirect 参数，登录成功后回到原页面。

router.beforeEach((to, from, next) => {
  const loggedIn = Boolean(localStorage.getItem('token'))
  if (to.meta.requiresAuth && !loggedIn) {
    next({ name: 'login', query: { redirect: to.fullPath } })
    return
  }
  if (to.name === 'login' && loggedIn) {
    next({ name: 'home' })
    return
  }
  next()
})

排查清单

  • 路由跳转没有反应，检查 push 的 name 是否和路由表一致。
  • 动态参数变化页面不刷新，watch route.params 或使用 beforeRouteUpdate。
  • 嵌套路由不显示，确认父组件中存在 router-view。
  • 线上刷新 404，确认 Nginx、Vercel、GitHub Pages 等部署环境已配置 fallback。
